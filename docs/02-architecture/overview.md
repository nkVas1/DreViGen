## 2. The central decision: a Rust core on every platform

Everything that is hard — the data model and its invariants, GEDCOM parsing, date arithmetic
across calendars, graph layout, phonetic matching, record linkage, the operation log, CRDT merge
— lives in Rust crates that are compiled **natively** under Tauri and **to WASM** for the web.

This buys three things that matter more than anything a shared UI framework could give:

1. **One implementation of correctness.** A date-interval comparison or a merge resolution cannot
   differ between the phone and the desktop, because it is the same machine code path.
2. **Performance where it is actually needed.** Layout of 50 000 nodes, a GEDCOM import of
   200 000 records, or a linkage pass over the whole tree are not JavaScript workloads.
3. **Testability.** The core is testable without a UI, at speed, including property-based tests
   over generated family structures.

The UI layer is then free to be ordinary, boring and excellent.

## 3. Platform strategy

**Tauri 2.11 from one codebase** → Windows, macOS, Linux, iOS, Android — plus an installable
PWA build of the same front end. Tauri closed its mobile gap in the 2025 releases; the Rust core
is shared with desktop, and the capability-based permission model covers the plugins we need
(filesystem, camera, biometrics, haptics, geolocation). Bundles land at single-digit megabytes
against Electron's hundred-plus. **[current]**

**The PWA is not a lesser tier.** It is how a relative in Chicago opens the tree on a borrowed
laptop without installing anything, and how the "always at hand" requirement is met on devices
we cannot ship to. It carries the full feature set except OS integrations that the web cannot
express. **It does not need cross-origin isolation** — spike S4 found that the OPFS VFS which
avoids `SharedArrayBuffer` is also the faster one, so COOP/COEP is dropped. See
[ADR 0008](./adr/0008-opfs-sahpool-single-connection.md).

## 4. Front-end stack, with reasons

| Layer | Choice | Reason |
|---|---|---|
| Framework | **React 19.3 + React Compiler** | Not the fastest framework — Solid and Svelte both beat it on microbenchmarks. Chosen for one decisive reason: **React Aria** is the best accessible-component primitive library in existence, and accessibility is this project's hardest constraint. Our performance-critical path is canvas and WASM, where the framework is not in the loop. The Compiler removes the memoisation boilerplate that used to be React's main cost. |
| Components | **React Aria Components** + own design system | WAI-ARIA-correct behaviour, keyboard and screen-reader handling, focus management — built and maintained by people who do nothing else. We style them completely; we do not reimplement them. |
| Styling | **Tailwind 4.3 with `@theme` tokens** + CSS Modules for bespoke surfaces | Tailwind 4 is CSS-first and natively OKLCH-aware, which fits the token pipeline. Anywhere the art direction gets genuinely custom (canvas overlays, plate frames, textures), plain CSS Modules. |
| Routing | **TanStack Router 1.170** | Type-safe routes and search params; search-param-as-state is exactly right for a canvas whose viewport should be linkable. |
| Server state | **TanStack Query 5.103** | Only for server-owned data (accounts, contributions, notifications). Domain data comes from the core, not from a cache. |
| UI state | **Zustand 5.0** | Small, unopinionated, no provider tree. Domain state is not kept here. |
| Motion | **Motion 13.4** + native View Transitions + CSS | Native first; the library where interruption handling or layout animation requires it. |
| Canvas | **Own renderer**, PixiJS 8.21 as substrate | See [layout-and-rendering.md](../01-research/layout-and-rendering.md) §5. |
| i18n | **ICU MessageFormat** via FormatJS + CLDR | See §7. |
| Build | **Vite 8.3**, **TypeScript 7.0** strict | TypeScript 7's native compiler makes strict type-checking fast enough to run on every save in a monorepo this size. |

### Frameworks not chosen

**Svelte 5** and **Solid** are both technically excellent and would produce smaller bundles.
Neither has an accessibility primitive library approaching React Aria's completeness. For a
product whose primary user is an 80-year-old, that gap outweighs the bundle-size difference —
particularly in a Tauri app, where the bundle is on local disk.

`apps/shell` and `apps/web` share `packages/app` entirely. The difference between them is the
bridge implementation and the platform capability set, nothing more. The shell is held to that:
if something works in the Tauri build and not in the browser, it belongs in the front end or in
the core rather than in the shell. What is in `apps/shell` is only what a browser tab cannot
do — one instance over one database, remembered window placement, a log file, and the window
frame, which the web page cannot reach.

How the six artefacts are built, and what each platform refuses to do until there is a
certificate, is in [release-and-distribution.md](./release-and-distribution.md).

## 6. Data flow

**Reads.** UI asks the core through the bridge. The core answers from SQLite, with hot
projections (the current viewport's people, the open person's dossier) cached in memory. The
canvas receives a compact typed-array view of layout positions and symbol attributes, not
objects — this is what keeps the render loop allocation-free.

**Writes.** Every mutation is an **operation** appended to the log, then applied to the
projection. The UI never mutates state directly; it dispatches an intent, the core validates it
against domain invariants, and either rejects it with a reason or commits it. Undo is a
traversal of the log, not a snapshot stack.

**Sync.** Explicit, user-initiated. See
[sync-and-collaboration.md](../01-research/sync-and-collaboration.md) §6.

## 7. Localisation

The family is distributed across Russia, the United States and Germany, so localisation is a
first-class subsystem rather than a string table.

- **ICU MessageFormat** for all interface copy — CLDR plural categories, gender and
  select/ordinal forms. Russian's four plural categories and German's grammatical gender both
  break naive interpolation, and genealogy text is unusually full of counted nouns ("3 ребёнка",
  "5 детей") and gendered verbs ("родился" / "родилась").
- **Launch locales:** `ru`, `en`, `de`. Architecture assumes more will follow.
- **Locale-aware genealogical formatting** — not the same problem as UI copy:
  - **Name order and composition.** Given + patronymic + surname vs given + surname; Hungarian
    and East Asian orders; particle handling in German and Dutch surnames.
  - **Grammatical case** in Russian relationship phrasing ("сын Ивана Петровича").
  - **Relationship terms.** Kinship vocabularies do not map one to one. Russian distinguishes
    *шурин*, *деверь*, *свояк* where English has "brother-in-law"; the relationship calculator
    emits a structured kinship path and the locale renders it.
  - **Dates** rendered per locale *and* per calendar, with the original always available.
  - **Transliteration** offered per target script, with the standard named (GOST / ISO 9 /
    BGN-PCGN / ALA-LC), never applied destructively.
- **Extraction and checks in CI.** Missing keys, unused keys and ICU syntax errors fail the
  build. Pseudo-localisation catches hard-coded strings and layouts that break on a 40 % longer
  German string.
- **RTL** is structurally supported from the start (CSS logical properties everywhere, no
  `left`/`right`), even though no launch locale needs it.

## 8. Security

| Concern | Measure |
|---|---|
| Authentication | Passkeys (WebAuthn) first; emailed magic link as fallback. No password to forget, satisfying WCAG 2.2 §3.3.8. |
| Transport | TLS only, HSTS, certificates automated by Caddy |
| Authorisation | Role checks server-side on every endpoint; the client's role is a UI hint, never a gate |
| At rest | Optional per-tree encryption of the local database; media encrypted at rest on the server when the tree is marked private |
| Living persons | Redaction applied at the serialisation boundary, so it cannot be bypassed by an export path |
| Supply chain | Pinned exact versions, committed lock files, `cargo audit` and `npm audit` in CI, Dependabot |
| Secrets | Environment only; `.env` git-ignored; secret scanning enabled on the repository |
| Uploads | Type sniffing, size limits, EXIF stripped from published derivatives (originals keep theirs) |

## 9. Testing strategy

Tests exist where they protect something that cannot be checked more cheaply — no coverage
theatre.

| Level | What it covers |
|---|---|
| **Unit (Rust)** | Date arithmetic, calendar conversion, phonetic codes, GEDCOM grammar, layout invariants |
| **Property-based (`proptest`)** | Generated family graphs: layout never places a child above a parent; GEDCOM round-trips are lossless; merge is commutative and associative |
| **Golden files** | GEDCOM fixtures from real-world exporters, byte-compared on round-trip |
| **Integration (Rust)** | Store + op log + sync against a real SQLite and a real Postgres |
| **Component (Vitest + Testing Library)** | Accessible name, role and keyboard behaviour of every design-system component |
| **E2E (Playwright)** | The core flows, keyboard-only, plus `axe-core` on every route |
| **Performance** | Frame-time budget on 10 k / 50 k / 200 k-person synthetic trees, tracked per commit |
| **Persona session** | Unassisted task list with the primary persona, once per phase. Failures are bugs. |

## 10. Open questions for Phase 0

1. **Loro at scale.** Does a 50 000-person tree with 100 000 operations fork, diff and merge
   within budget on a mid-range Android device? Fallback is Automerge 3.5.
2. **WASM core size.** The full core compiled to WASM must stay under a budget that keeps first
   paint acceptable; if not, the web build splits the core into an eager kernel and lazily
   loaded modules (ML, GEDCOM, layout).
3. **MSDF atlas coverage.** How much of the Cyrillic + Latin + Greek range can be pre-baked
   before atlas size becomes the bottleneck, and what is the on-demand rasterisation path.
4. ~~**OPFS concurrency.**~~ **Answered 2026-09-21** —
   [ADR 0008](./adr/0008-opfs-sahpool-single-connection.md). Integrity holds everywhere;
   throughput does not. One connection on `opfs-sahpool`, Web Locks for multi-tab.
5. ~~**Tauri mobile plugin coverage.**~~ **Answered 2026-09-21** —
   [mobile-capabilities.md](./mobile-capabilities.md). Official plugins cover everything except
   camera, photo library and share sheet; we write those, 12 days total.
